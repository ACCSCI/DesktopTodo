# Native SDK 待办小样粗测

2026-10-23，Windows 本机测量。按要求每档只采样一次，不做反复采样和启动排名。

实验使用真正的 Native SDK 0.11.0、Zig 模型、SDK 内置组件与 Geist 主题，无 WebView。
新增、完成切换、筛选、编辑锁定已接入；5 项编译无头测试通过。
实际 Windows 程序也通过了非空渲染、复选框点击与窗口数量检查。

| 实现 | 负载 | 进程数 | 工作集 MiB | 私有提交 MiB | 空闲 CPU，单核口径 |
|---|---|---:|---:|---:|---:|
| Native SDK | 1 便签 × 10 项 | 1 | 80.93 | 204.52 | 2.031% |
| C++ / Win32 | 1 便签 × 10 项 | 1 | 20.55 | 2.63 | 0.000% |
| Native SDK | 5 便签 × 100 项 | 1 | 112.83 | 234.59 | 7.031% |
| C++ / Win32 | 5 便签 × 100 项 | 1 | 21.57 | 3.52 | 0.000% |

SDK ReleaseFast exe：8,599,040 bytes，约 8.20 MiB。PDB 不计入 exe 大小。

## 如何理解

- 工作集是本次采样时驻留物理内存的页面；私有提交量不是物理驻留量。
- CPU 以一个逻辑核心占满为 100%；当前机器有 16 个逻辑处理器。
- 每档静置 2 秒，再测 10 秒，无快照轮询。数字不是长期平均，也不是性能保证。
- 全部是普通窗口、解锁状态、相同 680×760 物理外框，窗口重叠。统计完整进程树。
- 0.000% 仅表示该短样本未测到进程 CPU 时间增长。

## 范围与差异

本地锁定版本的 `UiApp` 默认只支持 4 个附加 UI 窗口；底层 Runtime 的窗口预算是另一回事。
本轮使用默认 UiApp，实际测 1 个主窗口加 4 个附加窗口，没有修改 SDK 上限或另写多运行时架构。
因此这里明确是 **5 个便签**，不是之前 WebView2 实验的 10 个便签。

SDK 小样暂存内存；C++ 对照版包含 SQLite。两者功能不齐平，结果只用于判断大概资源量级。
SDK 版尚无桌面嵌入、系统鼠标穿透、持久化、备份、自启动和拖拽排序。
SDK 自动截图里的中文出现黑块；尚未区分自动截图字形回退与系统窗口实际显示，中文显示没有验收。
现有 C++ 程序和真实数据库继续保留。

此次结果说明：当前 SDK 小样的工作集和私有提交高于现有 C++ 版。
这不是所有 Native SDK 应用的最低占用，亦未进行针对性调优。
